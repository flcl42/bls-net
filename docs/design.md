# Design

The library targets net10.0 and net11.0. Production arithmetic uses fixed-width value types, spans and limb operations, with no BigInteger or native dependency. Original APIs are variable-time for public inputs; explicit constant-time alternatives are described below.

## Layout and contracts

| Namespace | Contents |
|---|---|
| Arithmetic | Fp/Fr, Fp2/Fp6/Fp12, inversion, bounded wide intermediates and fused helpers |
| Curves | Affine/projective G1/G2, generic formulas, subgroup checks, scalar multiplication and MSM |
| Hashing | Field roots, SSWU, isogenies and cofactor clearing |
| Pairing | Miller loops, final exponentiation and pairing checks |

One console test project contains arithmetic, kernels, tower/pairing and curves/maps/MSM sections. One benchmark project contains all timing loops. They compile shared native interop and a single loader from `shared/`. Optional `external/blst` supplies the differential reference; outputs go under ignored `artifacts/`.

Field arithmetic generally uses `out result, in input...`, allowing output/input aliases. Curve and pairing APIs put the output last. Fp is a 48-byte canonical Montgomery residue in six little-endian 64-bit limbs (R = 2^384); Fr uses four limbs and R = 2^256. Public points and tower coefficients follow blst's memory layout, verified by differential tests. This does not imply wire-format compatibility.

Fp parsing accepts exactly 48 canonical big-endian bytes and rejects values at or above p. Raw G1 coordinates are X,Y; raw G2 coordinates are X.C0,X.C1,Y.C0,Y.C1. Affine infinity is all zero; projective infinity has Z = 0. Scalars are exactly 32 little-endian bytes per point, reduced modulo r. EIP-2537 padded fields and big-endian scalars need caller conversion.

Check the curve before checking a subgroup. Scalar multiplication and MSM require subgroup points; pairing callers must validate curves and subgroups. Empty MSM returns infinity; empty/all-infinity pairings return one/true. Mismatched spans and invalid scalar lengths throw ArgumentException. Map APIs accept field elements and return subgroup points; they do not hash messages.

## Portability

Production code uses portable integer operations, `Math.BigMul`, spans and fixed-size value types. ARM64 field kernels additionally use `ArmBase.Arm64.MultiplyHigh`, selected by the JIT-time constant `ArmBase.Arm64.IsSupported`; their portable high-half fallback permits direct x64 reference tests. There are no native production calls. Supported platform targets are little-endian x64/ARM64 on Linux, macOS and Windows. The test runner verifies field/tower/point sizes and coordinate offsets before running arithmetic. ARM64 defaults to expanded kernels; x64 keeps compact on .NET 10 and expanded on .NET 11+. Both overrides remain available. See [hardware measurements](performance.md#arm64-hardware) and [code-generation evidence](constant-time-validation.md#arm64-validation).

The optional native reference uses Cdecl imports. All field/point arguments cross the boundary through `in`/`out` references or explicit pointers, so no managed aggregate depends on ARM64 by-value struct rules. `ulong` maps to blst's `uint64_t` limb, `nuint` to `size_t`, and pointer tables retain native pointer width. The pinned C definitions export `int` predicates and an `int` conditional-negation flag, despite the public header spelling them `bool`; the imports match those definitions. No C `long` is imported. The loader uses the platform library extension and reports architecture mismatches instead of silently skipping a present binary. Windows ARM64 uses blst's MSVC assembly; Linux/macOS use upstream's shell build.

## Fields and extension tower

Multiplication uses two-row CIOS with final conditional reduction. Negation expresses p-a as p+~a+1, exposing carry chains and preserving zero with a mask. Fp inversion uses variable-time binary GCD: 31-bit top/bottom approximations form signed 2×2 matrices, followed by exact six-limb updates and modular coefficient corrections. Zero inverts to zero. Tower inversions reduce through norms to Fp inversion; Fermat inversion is an independent test reference.

| Type | Definition | Coefficient order | Bytes |
|---|---|---|---:|
| Fp2 | Fp[u]/(u²+1) | C0+C1u | 96 |
| Fp6 | Fp2[v]/(v³-(1+u)) | C0+C1v+C2v² | 288 |
| Fp12 | Fp6[w]/(w²-v) | C0+C1w | 576 |

Fp6 sparse helpers multiply by v, 0+yv or x+yv; `MultiplyByXY0` ignores the second input's C2. Fp12 sparse products pack coefficients into positions 0,1,4. Frobenius maps support powers 1–3. CyclotomicSquare matches blst's formula on arbitrary inputs, but equals ordinary square only in the cyclotomic subgroup.

## Runtime kernel policy

`Fp.UseExpandedKernels` is static readonly and follows the executing runtime, independently of the target framework: compact on .NET 10, expanded on .NET 11 and later. Small inlineable dispatchers select isolated optimized kernels. After field initialization, optimized callers fold the policy and remove the branch; cold dispatch also initializes policy before compiling a kernel.

Set AppContext switch `Nethermind.Crypto.BlsNet.UseExpandedKernels` before the first field use, or environment variable `BLSNET_EXPANDED_KERNELS` before process startup (`0`/`1`, or case-insensitive `false`/`true`). AppContext takes precedence; invalid environment values use the runtime default. Selection is fixed for the process. CLI `--compact-kernels`/`--expanded-kernels` switches exercise both formulas; expanded mode is slower on stock .NET 10 for x64.

Expanded symmetric Fp square computes 15 cross products once, doubles them, adds six diagonal products and performs six reduction rows: 57 widening products versus 72 for CIOS. Canonical inputs give a raw square below p² < pR and quotient below 2p. The bit-carry chain and delayed output preserve aliases. Compact square multiplies equal operands with CIOS.

Small public field operations remain inlineable. Composite callers isolate carry-heavy arithmetic to avoid JIT analysis limits and register pressure. `CurveField<T>` isolates Fp calls while Fp2 reaches its isolated kernels. `FpFused.Square` gives isolated squares and point formulas a concrete helper. `SquareNThenMultiply` retains lazy values across repeated squares and their final CIOS product. For inputs below 2p, each raw square is below 4p² < pR, so REDC stays below 2p inductively; the final multiplication returns a canonical value. Sqrt/Fp2-root chains use this kernel under either policy. x64 keeps six scalar limbs in the loop, with fixed memory operands and two modulus rows per iteration. ARM64 calls an isolated lazy-square leaf with whole product rows and six unrolled reduction rows; its public-count wrapper avoids the carry-analysis limits encountered when inlining the arithmetic into the loop. Neither loop canonicalizes intermediate squares. Full-word multiplication carries and one-bit addition carries stay in separate locals for the JIT proof. Some inline/non-inline helpers deliberately share formulas because call boundaries change generated code.

Stock RyuJIT materializes carries. [dotnet/runtime PR #134039](https://github.com/dotnet/runtime/pull/134039), head `0a303c9` or later, includes carry-aware lowering that retains them in flags. It also handles flag-preserving complements, multiply/add chains and conditional selections. The current component results also use the bounded [JIT follow-up](../jit/README.md): independent row matching, row-local multiplier copies, carry forwarding after final-limb search exhaustion, and mask-select/conditional-swap lowering. See [performance](performance.md#reproduction).

## Wide intermediates and bounds

ARM64 multiplication and REDC use separate whole-row chains for low products and shifted high products, with `mul`/`umulh` between flag consumers. The six Montgomery iterations are unrolled in an isolated leaf; the canceled low reduction word supplies its carry as `t0 != 0`. Correction reuses loaded modulus limbs. Inputs below 2p retain the existing `4p² < pR` bound, and field output remains delayed for aliases. The disjoint wide-product entry point stores completed low words as its rows finish; the ordinary wide product keeps all twelve words in scalars until both inputs are consumed. Both policies use that ARM64 alias-preserving specialization. The [ARM64 JIT patch](../jit/README.md#arm64-carry-and-row-follow-up) keeps carries and eligible selections in NZCV. x64 dispatches fold these ARM64 paths away.

Fr uses four unrolled ARM64 carry rows and reuses loaded modulus limbs for final subtraction. Canonical operands keep its Montgomery quotient below 2r < 2^256. Explicit final-word carry consumers avoid materializing intermediate flags. Fp subtraction and signed small-wide correction also reuse loaded modulus limbs. ARM64 Fp square has an isolated arithmetic leaf: inlining its full body into a caller loop can exceed carry/select analysis limits and produce many `cset`/`cmp` pairs. Its five-/four-/three-/two-product cross rows now use separate whole low/high carry chains. Both policies share this leaf. These paths retain delayed output assignment and input aliases.

FpWide is a signed twelve-limb, 768-bit intermediate, not a canonical field value. Expanded raw multiplication unrolls six rows. Reduction cancels the low 384 bits before adding the signed high half, avoiding a carry between rows. Compact mode keeps loops because expansion spills on stock .NET 10.

For R = 2^384, `ReduceWide` requires |x| < 3pR: its quotient lies in (-3p,4p), corrected by adding 4p when negative and reducing by 2p and p. ARM64 loads 4p/2p from a separate constant table and reuses the ordinary modulus for final correction. The table has a separate initializer so x64's existing field layout and initialization remain unchanged. `ReduceWideSmall` requires |x| < pR, giving (-p,2p), with one sign correction and final reduction. `ReduceWidePositive` requires 0 ≤ x < pR and skips sign correction in expanded mode. All return canonical values.

Expanded Fp2 multiplication uses three raw products and two reductions. Unreduced sums are below 2p; the real component has magnitude below p² and the imaginary lies in [0,2p²). The difference reducer avoids a twelve-word scratch round trip. ARM64 also keeps the imaginary component's two subtractions and positive REDC in one leaf, preserving all input/output aliases. `MultiplyWideNoAlias` requires output disjoint from both inputs; ordinary MultiplyWide preserves output overlap. All three Fp2 products finish before writing coordinates. Compact Fp2 multiplication keeps three CIOS calls. Square uses two CIOS products with policy-specific call boundaries. Expanded square keeps both in one kernel and uses a biased difference a+p-b in [0,2p), avoiding a canonical subtraction before multiplication. The product of its two unreduced factors is below 4p² < pR.

WideTower combines raw Fp2/Fp6 products before final reduction. Product bounds are 8p² for Fp6, 9p² for sparse Fp12 and 22p² for full Fp12; the first two fit pR and the last fits 3pR < 2^767. Expanded Fp6 square uses twelve raw products and six reductions. Its first two Fp2 components fit 8p²; C2 can reach 12p² and needs the full reducer. Narrow inputs and wide scratch must be distinct. ARM64 uses the disjoint raw-product entry for these buffers and forms the two diagonal products' sum in registers before subtracting it from the imaginary product. Rearranging the additions modulo 2^768 preserves signed-wide values and avoids an intermediate wide store/reload.

FpFused/Fp2Fused combine canonical product sums/differences before reduction. Base sums are in [0,2p²), differences have magnitude below p². Complex differences and real sums have magnitude below 2p²; imaginary sums lie in [0,4p²). Inputs are consumed before output assignment, including scalar-coefficient aliases. New lazy formulas must establish their bounds before choosing a reducer. ARM64 Fp4 squaring keeps three Fp2 squares wide, with biased real products below 4p². Their final combinations have magnitude below 8p² < pR, so four bounded reductions replace six CIOS reductions. The imaginary coordinate of the first result is nonnegative and uses positive REDC; the other coordinates use signed small REDC. This larger biased bound is private to Fp4 and does not change the tighter Fp6/Fp12 wide-product proofs. Multiplication by eight in the doubling helper shifts a canonical value (8p < R), then conditionally subtracts 4p, 2p and p; no intermediate canonical doubles are needed.

## Curves, scalars and MSM

Generic Jacobian formulas specialize to Fp/Fp2 through IField<T>; its public contract remains stable. Fixed cofactor doubling runs retain local coordinates and split preparation/completion into bounded kernels, inlining linear arithmetic while keeping products isolated. G1 uses 4S+3M, G2 retains 5S+2M; both produce the same Jacobian coordinates as ordinary doubling. Other field types retain the generic loop. XYZZ buckets cache Z²/Z³. CurveConstants contains the endomorphism and subgroup constants. Scott subgroup checks and deterministic cofactor relations avoid probabilistic validation.

G1 scalar multiplication uses a GLV split into two 128-bit components; G2 uses four base-|z| GLS digits and psi images. Joint width-5 wNAF builds eight odd multiples only for the original point, batch-normalizes them, then derives endomorphism images.

MSM uses the single-multiply path at n=1. G1 splits inputs with 2 ≤ n < 1,024 into 2n effective points with 128-bit scalars; larger G1 inputs keep 256-bit scalars. G2 with n ≥ 2 splits into 4n effective points with 64-bit scalars. Reduced scalar slots clear unused bytes; Booth extraction includes a top carry window.

Up to 32 effective points use signed width-4 tables and one batch inversion. Larger MSMs use Pippenger with signed Booth windows and XYZZ buckets. If l=floor(log2(effective points)), projective width is l-3 for l>12, l-2 for l>8, l-1 for l>4, otherwise 2. The 128-bit path uses one smaller window for 128–256 effective points.

Batch-affine buckets group by digit and add in balanced rounds with one batch inversion per round, using width max(2,projective width-1). Thresholds count effective points: G1 starts at 512 in either mode; expanded G2 starts at 128, compact G2 retains XYZZ. Repeated points double, inverse points cancel and infinity is skipped. A cancelled bucket must retain zero ZZ/ZZZ when converted back to XYZZ. Storage is bounded stack or pooled arrays; initial pool growth may allocate.

## Maps and pairing

Maps apply optimized SSWU, homogeneous 11-isogeny (G1) or 3-isogeny (G2), then cofactor clearing by 1-z or a psi formula. Fixed reciprocal-square-root chains select candidates and sign; G2 specializes pure-imaginary/equal constants. Isogenies compute only needed powers (16 for G1, four for G2). Expanded Horner and point completion fuse product differences. Native comparisons and independent affine polynomial identities cover rescaled inputs and aliases. Cofactor clearing uses psi²(X,Y,Z)=(beta*X,-Y,Z). Secret maps omit doubling candidates only at additions proven distinct by group-order gcds or Frobenius norms, retaining masked infinity handling. The complete formula remains at the possible G1 3-/11-torsion and G2 13-torsion doublings. The [proof and full-curve tests](cofactor-schedule.md) do not assume prime-subgroup inputs.

Miller loops use blst's line formulas and negative-z schedule. Up to 64 active pairs share a pass and accumulator squarings; larger inputs multiply pass results. Scratch is sized to min(64,input count). Infinity pairs are skipped. Expanded batches combine adjacent lines into a five-coefficient product: 69 Fp products/22 reductions versus 78/24 for separate sparse products. The first line pair initializes the accumulator; odd lines use ordinary sparse multiplication. Compact mode retains separate lines.

Final exponentiation uses inversion, conjugation and Frobenius for the easy part, followed by blst's fixed z/z÷2 chain. Runs of at least 15 squarings use Karabina compression (ePrint 2010/542, Theorems 3.1–3.2), keeping four Fp2 coordinates. Two Fp4 squares update them; one Fp2 inversion reconstructs omitted coordinates. Zero/identity and aliases are explicit. Compression replaces 235 of 315 squares with ten reconstructions, saving 1,248 logical Fp products at the cost of ten base inversions. Repeated cyclotomic square requires cyclotomic input or zero. PairingCheck returns immediately if the Miller product is one.

## Constant-time APIs

The following paths treat field values, scalar bytes, point coordinates, infinity status, equality results and every intermediate derived from them as secret. The point supplied to multiplication may also be secret. Span lengths, kernel policy, type specialization, curve constants, fixed exponents and window/loop counters are public. Scalar multiplication still requires an on-curve subgroup point; validation is the caller's responsibility and the existing validation methods are variable-time.

| API | Contract |
|---|---|
| `Fp.InverseConstantTime`, `Fp2.InverseConstantTime`, `Fr.InverseConstantTime` | Fixed blst binary-GCD schedules: 768 steps for Fp, 512 for Fr; Fp2 inverts its norm. Zero maps to zero, output may alias input, and Montgomery output is canonical. |
| `Fr.FromLittleEndianConstantTime`, `ToLittleEndianConstantTime` | Reduce exactly 32 secret little-endian bytes modulo r, or serialize 32 canonical little-endian bytes. Two trial subtractions suffice because 2^256 < 3r. Length errors depend only on public lengths. |
| `Fp` / `Fp2` / `Fr`: `IsZeroMask`, `EqualMask`, `Select`, `ConditionalNegate`, `ConditionalSwap` | Masks are `ulong.MaxValue` for true and zero for false. A select takes the set operand first. Callers must supply one of those two masks. Operands and masks may all be secret; aliases, including swapping the same reference, are supported. |
| `Fp` / `Fp2`: `SqrtConstantTime`, `SignMask` | Return a square-status mask or RFC 9380 sign mask. Square roots match the existing helpers, including their output for nonsquares; only use the root when the status mask is all ones. Zero is a square. |
| `G1Projective` / `G2Projective`: `MultiplyConstantTime` | Affine and projective overloads; exactly 32 little-endian bytes, reduced modulo r first. Secret base point and scalar, fixed GLV/GLS split, width-five Booth windows, full-scan tables and select-based exceptional handling. Infinity and scalar zero are supported. Projective output may alias input. |
| `G1Projective` / `G2Projective`: `ToAffineConstantTime`, `AddConstantTime`, `AddAffineConstantTime`, `NegateConstantTime` | Secret points throughout; affine infinity is (0,0), projective infinity has Z=0. Additions cover equal, inverse and infinity operands using blst's dadd/dadd_affine formulas. Conversion always performs the fixed inversion, even for Z=0 or Z=1. |
| Affine and projective G1/G2: `IsInfinityMask`, `EqualMask`, `Select`, `ConditionalNegate`, `ConditionalSwap` | Secret operands and mask; projective equality uses cross products and handles any Z=0 representation. Affine infinity is preserved by negation. |
| `MapToCurve.MapToG1ConstantTime`, `MapToG2ConstantTime` | Secret Fp/Fp2 input; same SSWU, isogeny and cofactor map as the original APIs and blst's single-input maps. Candidate roots, denominator exceptions and signs use masks. These methods do not hash a message. |

The scalar split uses fixed 256-step binary division with explicit limb borrows instead of blst's assembly reciprocal-division kernels. G1 produces two 128-bit components with the existing beta-squared/negation endomorphism; G2 produces four base-|z| components with successive -psi images. The window loop includes the top carry window and scans all 16 table entries even for a zero digit. Tables remain projective, avoiding inversions and secret-dependent normalization. Existing doubling formulas already handle Z=0 algebraically. Scalar reduction and splitting use no division on secret data or variable-time recoding. Some runtime Tier0 versions divide public window counts and type sizes; the generated-code audit classifies those operands explicitly.

### Fixed binary-GCD inversion

The ARM64 31-step kernel gates subtraction by parity, then uses its borrow for three conditional selections. The other packed coefficient row is recovered from the invariant sum of both rows. This removes rollback selects while retaining the same 31-bit schedule, coefficient bounds and correction. The original x64 loop remains selected on x64; direct batch tests compare both formulations with the independent matrix model.

The inverse ports pinned blst's `ctx_inverse_mod_384-x86_64.pl`, `ct_inverse_mod_256-x86_64.pl`, `no_asm.h` and `recip.c`. This is [Pornin's optimized binary GCD](https://eprint.iacr.org/2020/972), Algorithm 2 and Appendix A, in the safegcd family; it is distinct from [Bernstein–Yang's delta-based divsteps](https://gcd.cr.yp.to/safegcd-20190413.pdf). [Wuille's safegcd-bounds analysis](https://github.com/sipa/safegcd-bounds) concerns that latter algorithm and its half-delta variant. Their different iteration bounds must not be interchanged.

With Pornin's k=32, each approximation combines 33 common high bits and 31 exact low bits. The inner loop performs compare/swap/subtract and rolls back on an even input, using masks in C# and conditional moves on the patched JIT. Each matrix row packs two biased 32-bit coefficients. Apply the signed matrix, divide exactly by 2^31, take absolute values and negate the corresponding rows when necessary. Algorithm 2 and Appendix A prove at least 31 bits of combined bit-length reduction per batch until termination. The bound is 2n-1 for an n-bit odd modulus: 761 for p and 509 for r. The pinned ADX assembly also uses **31-bit** batches.

The public schedule is **23×31+55=768** for Fp and **15×31+47=512** for Fr. The tail is one exact low-word loop, combining the last two iterations. For nonzero input the initial combined bit lengths are at most 762/510. After Fp's first 19 batches they are at most 173, so both operands fit the three-limb update's 191-bit contract. After 23/15 batches they are at most 49/45, so the exact tail fits one word. Zero is separate in the argument, not the control flow: a and v stay zero; late Fp updates truncate b to its low three limbs. Every resulting matrix still has rows (1,0) and (0,2^31), so this truncation cannot affect the zero result.

Let N=384 or 256, R=2^N, x be the Montgomery input and t the completed step count. The invariant is u*x=a*2^t and v*x=b*2^t modulo the modulus. Each row's absolute coefficient sum is at most 2^s for s steps; hence |u|,|v|≤2^t. This gives the following storage schedule, with zero-based batch indices:

| State | Fp | Fr | Width argument |
|---|---|---|---|
| a,b | Six limbs through batch 18, three thereafter | Four limbs throughout | Combined-length contraction above; one unsigned excess product word before shifting |
| First two cofactor batches | Signed scalar initialization | Signed scalar initialization | Growth ≤2^62, so signed 64-bit arithmetic suffices |
| u | Seven limbs throughout | Five limbs throughout | Retain blst's signed-row cofactor bound abs(u)<R, with an explicit sign/excess word |
| v, early | Seven limbs through batch 11 | Five limbs through batch 8 | Growth ≤2^372 / 2^279, below the signed capacities 2^447 / 2^319 |
| v, late | Twelve limbs | Eight limbs | Growth before the tail ≤2^713 / 2^465, below signed 2N-bit capacity |
| Final cofactor | Twelve limbs plus top word | Eight limbs plus top word | Growth ≤R², so the top word is -1, 0 or 1 |

The narrow-u argument is the signed cofactor bound used explicitly in [pinned blst's signed-product contract](https://github.com/supranational/blst/blob/f62244ef50ad1a603decdb8f215e982d2a467bb6/src/asm/ctx_inverse_mod_384-x86_64.pl#L409-L421), in the comment introducing its signed product helpers: u stays within N bits; once v exceeds that width the a row is already (1,0). Therefore the discarded high v words in the narrow u update multiply zero, and the wide v update needs only a sign-extended narrow u product. This is an additional cofactor property of that port, not a consequence of length contraction alone. The exact determinant invariant is u*b-v*a=±m; for positive exact steps with opposite coefficient signs it bounds the live coefficients by m. The independent signed BigInteger batch model checks the stronger |u|≤m and |v|≤m while a is nonzero, the (1,0) row after growth, every scheduled result including sign/excess words, and the approximation/sign corrections. It includes the raw worst-case inputs 2^380 and 2^254, which attain the classic 761/509 bound. These executable checks supplement the imported bound; they are not an exhaustive proof.

Signed products conditionally negate the input according to the multiplier sign, then multiply by the absolute multiplier with row-first `MulAdd` chains. Complete unsigned accumulation rows expose MULX/ADCX/ADOX without per-limb signed-product repairs. Narrow cofactors have N/64+1 words, not just the field's word count: Fr's early v can genuinely exceed 256 bits. Helpers consume inputs before assigning output, preserving aliases. The 31-step loop is inlined so matrices stay in locals; product helpers remain isolated because indiscriminate inlining exhausts the JIT budget and breaks carry-row recognition.

The final cofactor v satisfies v*x=R² modulo the modulus for nonzero x. Blst's precomputed left-aligned modx is 8p or 2r. Adding modx*R to a negative v at most twice, or subtracting it at the positive R² endpoint, puts v in [0,R²). Since R<16p and R<4r respectively, canonicalize the high half with fixed trial subtractions (8p,4p,2p,p or 2r,r), reduce the low half by Montgomery REDC and add them; the sum is below twice the modulus. One final canonical reduction followed by Montgomery multiplication with R² yields x^-1*R², the inverse in Montgomery form. This version accepts the entire [0,R²) correction range, rather than assuming a tighter cofactor bound. Tests cover the correction endpoints and all subtraction thresholds independently.

All loop counts and offsets are public constants. Approximation scans every fixed limb with masks; its secret normalization count feeds only hardware shifts, never indexing or loop bounds. No secret division, branches, allocation or BigInteger is used. [Runtime validation](constant-time-validation.md#fixed-binary-gcd-inversion-validation) records the generated instructions and timing experiments. The old Fp/Fr Fermat reciprocal chains are removed; fixed square-root chains remain because inversion does not compute a square root. Variable-time `Fp.Inverse` retains its variable batch schedule; on ARM64 its full 31-step batches reuse the existing signed fixed-width update helper and an unrolled modular coefficient update. The latter uses |f|+|g|≤2^31 to retain the existing (-p,2p) correction bound. Shorter batches and x64 keep the span implementation. Constant-time inverse schedules and helpers are unchanged.

Verification combines BigInteger scalar/inverse references, comparison with the original APIs, optional native blst comparisons, aliases, exceptional point cases, scalar boundaries and every single-bit scalar, and thousands of random field/map/point inputs under both kernel policies. [Constant-time validation](constant-time-validation.md) records the runtime matrix, generated-code audit and opt-in Welch timing experiments. The audit inventories conditional jumps, direct callees, memory-address instructions and variable-latency instruction candidates; manual data-flow review is necessary. A timing experiment that fails to detect leakage is evidence for that capture, not a proof.

Only the recorded Windows x64 runtime/JIT configurations have been audited. JIT-generated code is audited, not formally verified; repeat the audit after runtime, architecture, compiler settings or relevant source changes. These APIs do not protect against power/EM side channels, memory disclosure or physical attacks, and do not promise to erase every JIT/register/stack copy. They provide building blocks for a later signing API, which still needs a security review, message hashing, encodings and protocol-level validation. The original variable-time APIs and MSM retain their public-input contracts.

## Verification and limits

BigInteger references, Fermat inversion, signed-wide bounds, algebraic identities, canonical parsing, aliases and warmed allocation checks complement native comparisons. Native coverage includes field/tower results, 2,000 maps and single scalars per group, scalar edges and all single-bit scalars, MSM through 1,024 points, and 2,000 pairing inputs. Fp6 is checked algebraically and through Fp12, without custom native exports. Pairing tests cross the 64-pair batch boundary through 130 pairs with infinity gaps, bilinearity and true/false products. Console options also check cold initialization and optimized policy folding.

The original binary GCD, recoding, table/bucket selection and exceptional point handling depend on inputs. Use the explicit constant-time alternatives for secrets within their audited configurations; a complete secret-key/signature API still needs security review. See [README](../README.md#build-and-test) for commands and [roadmap](roadmap.md) for remaining APIs and platform work.
